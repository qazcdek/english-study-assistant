# ONGOING

> **층** 진행 · **상태** 유효 · **강제** `backend/tests/test_doc_references.py`
> **읽어야 할 때** **진행 중인 일을 집거나 놓을 때.** 남이(또는 내일의 내가) 이어받을 때
> **위** [문서 지도](../00-index.md) · **함께** [ROADMAP](ROADMAP.md) · [ISSUES](ISSUES.md) · [DONE](DONE.md)

**지금 열려 있는 일의 세부.** `[~]` 인 태그만 여기 있고, 끝나면 [DONE](DONE.md) 으로
옮기고 이 문서에서 **지운다.**

```
ROADMAP · ISSUES   [ ]  한 줄.  무엇을 할지만
      ↓ 시작하면서  [~]
ONGOING            진행하면서 적는다.  계속 고친다
      ↓ 끝나면     [x]
DONE               무엇을 / 왜 / 어떻게.  **다시 고치지 않는다**
설계 문서           판단이 반영된다.  계속 유효하다
```

## 왜 이 문서가 필요한가

전에는 세부를 둘 자리가 **DONE 뿐**이었다. 그런데 DONE 은 **끝난 뒤에** 쓰는 문서다.
그래서 아직 안 한 일의 세부는 **어디에도 없었고**, 한 줄 요약이 그 역할을 떠맡았다.

한 줄은 길이가 모자란 게 아니라 **틀려도 맞아 보인다.** 실제로
`M2-T1 작문 연습 결과를 저장 — 지금은 채점하고 버린다` 가 그랬다. 저장은 **이미 되고
있었는데**, 그 한 줄이 그럴듯해서 아무도 의심하지 않았다. 코드를 읽고서야 알았다.

그래서 이 문서의 첫 칸이 **전제**다. "지금 어떻게 돼 있나" 와 **어디서 확인했나**를
함께 적는다. 확인 출처가 없는 전제는 짐작이고, 짐작은 조용히 낡는다.

## 형식

```
### <태그> · <한 줄 요약>
시작 <날짜> · 갱신 <날짜>

- **전제** 지금 어떻게 돼 있나. **어디서 확인했나**를 함께 적는다
- **결정** 무엇을 하기로 했나, 왜. 버린 안도 적는다
- **막힌 것** 못 가는 이유 — 물어야 할 것, 재야 할 것
- **다음 걸음** 바로 다음에 할 하나
```

네 칸을 다 채울 필요는 없다. 다만 **전제와 다음 걸음**은 비워 두지 않는다 —
그 둘이 없으면 내일 이어받을 수 없다.

### H-046 · 예문의 한국어 대역이 주어를 바꿔 옮긴다
시작 2026-11-03 · 갱신 2026-11-03

- **전제** 글감 예문 9개 중 2개에서 대역이 주어를 바꿨다 — `She acted in defiance
  of…` → "**그는** 부모님의…", `The country decided to annex…` → "**그 도시는**
  더 작은 영토를…". 사람이 읽으면 바로 보이지만 검사는 못 본다.

- **한 일** `M16` 이 예문 규칙을 다시 쓰면서 **금지 조항을 넣었다** —
  "주어와 인물을 바꾸지 않는다. `She acted…` 는 '그녀가…' 이고 '그는' 이 아니다."
  정오 예시를 함께 적었다 (`prompts/analysis.py` 의 `_EXAMPLE_RULE`).

- **막힌 것** **고쳐졌는지 코드로 확인할 수 없다.** 대역의 주어가 맞는지는 LLM
  응답 품질이고, `CLAUDE.md §6.7` 이 그런 것은 직접 보고 확인하라고 적어 둔
  자리다. 규칙이 든 것은 검사가 지키지만(문구가 사라지면 실패한다) **효과는
  다음 글감의 예문을 눈으로 봐야** 안다.

- **다음 걸음** `M13-T4` 가 운영에서 글감을 고르면 그 예문 대역을 읽어 본다.
  두 개 중 하나라도 또 어긋나면 금지 조항만으로는 모자란 것이므로, 대역을
  **별도 파트로 빼서** 원문 주어를 입력으로 주는 쪽을 검토한다.

### H-032 · 검사와 cloud 개발이 운영과 다른 엔진에서 돈다
시작 2026-10-23 · 갱신 2026-10-23

- **전제** 네 군데서 DB 를 띄우는데 **운영만 Postgres** 다.

  | 어디 | 엔진 | 확인한 곳 |
  |---|---|---|
  | 단위 검사 (로컬) | SQLite | `tests/conftest.py` · `tests/modes.py` |
  | CI | SQLite | `.github/workflows/ci.yml` — 서비스 컨테이너가 없다 |
  | local 모드 띄우기 | Postgres 17 (도커 15432) | `app/config.py` 의 기본값 |
  | cloud 모드 띄우기 | SQLite | `backend/.env.cloud` 의 `DATABASE_URL` |
  | 운영 (Render) | Neon Postgres | `07-web-deployment.md` |

  **이미 두 번 물렸고, 둘 다 글로 막아 뒀다.** `String` 길이를 SQLite 는 무시하고
  Postgres 는 `value too long` 으로 거부한다 (`tests/test_migrations.py` 의
  주석), SQLite 는 `PRAGMA foreign_keys` 가 꺼져 있으면 CASCADE 가 아예 안 돈다
  (`14-data-layer.md §3.3`). 둘 다 "그러니 조심해라" 로 끝난다 —
  **선언이고 장치가 아니다** (`12-tooling.md §6`).

  주석도 이미 어긋나 있었다. `app/db/session.py` 와 `app/main.py` 가
  "local 은 docker Postgres, cloud 는 Neon" 이라고 적는데 `.env.cloud` 는 SQLite 다.

- **결정** 세 층을 **다르게** 다룬다. 전부 Postgres 로 바꾸지 않는다.

  1. **검사는 양쪽에서 돈다.** 기본은 SQLite 로 두고 (빠르고 오프라인에서 돈다),
     `TEST_DATABASE_URL` 이 있으면 그 Postgres 에서 돈다. **CI 가 Postgres 쪽을
     맡는다** — 머지 게이트가 운영 엔진을 보는 것이 핵심이고, 로컬 반복 속도는
     그대로 둔다. 둘 다 돌리려면 `./dev.sh test --pg`.
  2. **격리는 스키마로 한다.** 테스트마다 DB 를 만들면 느리고, 하나를 공유하면
     서로의 행을 지운다. URL 에 `options=-csearch_path%3D<스키마>` 를 실어
     테스트마다 스키마 하나를 만들고 끝나면 지운다 — **쳐 보고 확인했다**
     (두 스키마가 같은 이름의 표를 각자 들고 서로를 못 본다).
  3. **cloud 모드 띄우기는 Neon 의 별도 브랜치로** 옮긴다. 도커 Postgres 로도
     엔진은 맞지만 **버전·연결 수 제한·콜드 스타트가 다르다.** 같은 서비스의
     브랜치면 그것까지 같아진다.

  **운영 저장소를 가리키지 않는다.** 앱은 뜰 때 `upgrade head` 를 돌리고
  (`app/db/migrate.py`), 개발 중에는 `downgrade` 도 돈다 — 운영 DB 에 걸면
  회원 데이터가 사라진다.

  **문서도 같이 어긋나 있었다.** `07-web-deployment.md §6.4` 가 cloud 를 띄우는
  방법으로 `sqlite+pysqlite:///./local-cloud.db` 를 안내하고 있었다 — 결정 3항과
  정면으로 반대고, `./dev.sh cloud` 의 장치가 **거부하는 것**을 적어 둔 셈이다.
  `09 §6.4` 를 쓸 때 짝을 못 찾았다 (`CLAUDE.md §5.1-7`). 고쳐서 `09` 를 가리키게 했다.

- **다음 걸음** 사용자가 Neon 에 `dev` 브랜치를 만들어 `.env.cloud` 의
  `DATABASE_URL` 을 바꾼다 — 절차는 `07-web-deployment.md §6.4`.
  그 뒤 cloud 모드를 띄워 두 모드를 모두 확인한다.
