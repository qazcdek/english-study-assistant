# 08. 난이도 설계 (기획안)

> 상태: **기획안**. 구현 전에 결정이 필요한 항목을 9절에 모았다.

## 1. 지금 무엇이 문제인가

난이도(`beginner` / `intermediate` / `advanced`)가 실제로 바꾸는 것은 **프롬프트에 끼워 넣는
문단 하나뿐**이다. 그 문단은 이렇게 생겼다.

```
초급  "문법 용어를 최소한으로 쓰고 풀어서 설명한다"
중급  "일반적인 문법 용어를 써도 좋다"
상급  "설명을 깊게 한다 — 뉘앙스 차이, 어원, 비슷한 표현과의 비교…"
```

전부 **형용사와 정도부사**다. "최소한으로", "깊게"가 무엇인지 모델도 모르고 우리도 모른다.
검증할 수도 없다 — 어떤 출력이 "충분히 깊은지" 판정할 기준이 없기 때문이다.

이 프로젝트에서 같은 종류의 실패를 이미 세 번 겪었다.

| 애매한 지시 | 실제로 벌어진 일 | 해결 |
|---|---|---|
| "학습 가치가 낮은 기초 어휘는 제외" | 모델이 "기초 단어가 아니면 통과"로 읽어 `financial advisor` 같은 투명한 복합어만 뽑음 | 비합성성이라는 **판별 기준** + 정오 예시 (04-prompt-design 2.1.1) |
| "표현은 3~8개" | 하한만 맞추고 멈춤 | 스키마 `minItems`/`maxItems` **토큰 단계 강제** (2.1.2) |
| "①②③을 순서대로 쓴다" | ③을 "~하는 데 도움을 준다" 같은 일반론으로 때움 | 필드를 넷으로 **쪼개고 `required`** (2.4) |

**교훈은 하나다. 프롬프트로 부탁하면 안 지켜지고, 스키마로 요구하면 지켜진다.**
난이도도 같은 방식으로 다시 설계한다.

여기에 더해, 난이도를 **개수**에 연결했다가 상급 결과가 중급보다 쉬워지는 역전까지 겪었다
(`a blend of` → `blend`). 개수는 이미 난이도에서 떼어냈다.

## 2. 무엇을 기준으로 난이도를 가를 것인가

임의로 정하지 않기 위해 영어교육에서 쓰는 틀을 빌린다.

### 2.1 Form – Meaning – Use (Larsen-Freeman)

하나의 언어 항목을 가르칠 때 다뤄야 할 세 축이다.

| 축 | 묻는 것 | 예: `weigh in on` |
|---|---|---|
| **Meaning** | 무슨 뜻인가 | 의견을 내다 |
| **Form** | 어떻게 생겼나 | 자동사구. 대상 앞에 `on` 이 붙는다. `weigh in on 명사` |
| **Use** | 언제·왜 이걸 쓰나 | 공적 사안에 격식 있게 개입할 때. 사적 잡담에는 과하다. `comment on` 보다 무게가 있다 |

**난이도는 이 세 축 중 몇 개를 다루는가로 가른다.** 형용사가 아니라 항목의 유무다.

```
초급   Meaning
중급   Meaning + Form
상급   Meaning + Form + Use
```

이 축은 관찰 가능하다. 출력에 Form 정보가 있는지 없는지는 사람이 세어서 확인할 수 있다.

### 2.2 무엇을 고를 것인가 — 빈도대

무엇을 다루는가도 난이도에 따라 달라야 한다. 어휘 교육에서 쓰는 빈도대를 쓴다.

| 난이도 | 대상 | 예 |
|---|---|---|
| 초급 | 일상에서 자주 마주치지만 **낱말 뜻으로 짐작이 안 되는** 것 | `get it`, `bail on`, `wanna` |
| 중급 | 신문·업무 글에서 흔한 것 | `weigh in on`, `cope with`, `a blend of` |
| 상급 | 특정 분야·격식 글에서만 보이거나 **유사 표현과 미묘하게 갈리는** 것 | `pass muster`, `trumpet`(비유), `grow` 의 타동사 용법 |

비합성성이라는 선정 기준은 세 난이도 공통이다. 난이도는 그 안에서 **어느 빈도대를 고르는가**를
바꾼다. 초급에서 `pass muster` 를 뽑거나, 상급에서 `get it` 을 뽑는 것은 둘 다 실패다.

### 2.3 문법 용어 사용 범위

"문법 용어를 최소한으로"를 목록으로 바꾼다.

| 난이도 | 쓸 수 있는 용어 |
|---|---|
| 초급 | 주어, 동사, 목적어, 시제, 단수/복수 정도. 그 밖에는 풀어서 쓴다 |
| 중급 | 관계절, 분사구문, 형식주어, 수동태, 가정법, 조동사 등 학교 문법 범위 |
| 상급 | 위 + 정보구조(초점·주제), 화용, 사용역(register), 연어·문형(colligation) |

## 3. 난이도별 정의 (요약)

| | 초급 | 중급 | 상급 |
|---|---|---|---|
| 다루는 축 | Meaning | Meaning + Form | Meaning + Form + Use |
| 대상 빈도대 | 일상 고빈도 | 신문·업무 | 분야·격식·미묘한 차이 |
| 문법 용어 | 최소 목록 | 학교 문법 | + 정보구조·화용·사용역 |
| 표현 개수 | 3~5 | 5~8 | 5~8 (중급과 동일) |
| 구문 해설 수 | 0~2 | 2~4 | 3~5 |
| 한 항목당 분량 | 짧게 | 보통 | 길어짐 |

**개수는 난이도를 따라 늘리지 않는다.** 상급의 차이는 개수가 아니라 항목당 정보량이다
(1절 참고).

## 4. 파트별 구체안

### 4.1 표현 풀이

난이도가 바꾸는 것은 **필수 필드**다.

| 필드 | 초급 | 중급 | 상급 |
|---|---|---|---|
| `expression` `type` `meaning` | 필수 | 필수 | 필수 |
| `example` `example_ko` | 필수 | 필수 | 필수 |
| **`form`** — 문형·활용·함께 쓰는 전치사 | — | **필수** | **필수** |
| **`usage`** — 사용역·유사 표현과의 선택·피할 자리 | — | — | **필수** |

```
초급   bail on
       meaning  (약속·계획에서) 갑자기 빠지다

중급   weigh in on
       meaning  의견을 내다
       form     자동사구. 대상 앞에 on 이 온다 — weigh in on + 명사

상급   pass muster
       meaning  기준을 충족하다
       form     보통 부정문·의문문으로 쓴다 — didn't pass muster
       usage    공적 심사를 통과한다는 뜻이라 일상 대화에는 과하다.
                meet the standard 보다 "심사자가 있다"는 함의가 강하다
```

`meaning` 안에 이 모든 것을 섞어 쓰라고 부탁하는 대신, 필드를 나눠 `required` 로 묶는다.
구문 해설에서 효과를 확인한 방식이다.

### 4.2 문장 구조

| 필드 | 초급 | 중급 | 상급 |
|---|---|---|---|
| `fragment` `name` `role` | 필수 | 필수 | 필수 |
| `rewrite` | 필수 | 필수 | 필수 |
| `pitfall` | — | 필수 | 필수 |
| **`why`** — 글쓴이가 왜 이 구조를 골랐나 (정보구조·초점) | — | — | **필수** |

초급의 `name` 은 용어 대신 풀어 쓴다: "if 를 생략한 도치 가정법" → "만약 ~였다면 을
거꾸로 쓴 형태".

상급의 `why` 예: "행위자를 밝히지 않아 책임 소재를 흐리고, 규칙 자체가 주체인 것처럼 읽힌다."

### 4.3 총평

난이도가 바꾸는 것은 **코멘트의 초점**이다. 필드는 같다.

| 난이도 | `comment` 가 답해야 할 질문 |
|---|---|
| 초급 | 이 표현들을 어디서 또 만나게 되나 |
| 중급 | 직접 써도 되는 것과 알아만 둘 것의 구분 (현행) |
| 상급 | 이 글의 사용역에 맞춰 쓰려면 무엇을 지켜야 하나 |

### 4.4 작문 연습

채점 피드백의 깊이도 난이도를 따른다. 현재 `LEVEL_GUIDE` 가 프롬프트 한 줄로만 조정한다.

| 난이도 | `target_note` 가 다루는 것 |
|---|---|
| 초급 | 목표 표현을 썼는가, 뜻이 통하는가 |
| 중급 | + 문형·전치사가 맞는가 |
| 상급 | + 더 자연스러운 대안이 있는가, 사용역이 맞는가 |

## 5. 어떻게 강제할 것인가

**프롬프트 문단이 아니라 스키마로 강제한다.** `PartSpec.schema_for(level)` 이 이미 있으므로
필드 목록을 난이도별로 바꾸는 것으로 확장한다.

```python
# 지금: 개수만 난이도별로 바꾼다
def schema_for(self, level): ...  # minItems / maxItems 만 조정

# 제안: 필수 필드도 난이도별로 바꾼다
FIELDS_BY_LEVEL = {
    "beginner":     [...기본],
    "intermediate": [...기본, "form"],
    "advanced":     [...기본, "form", "usage"],
}
```

Pydantic 모델은 상위 집합 하나로 두고(`form`/`usage` 는 기본값 `""`),
**스키마의 `required` 만 난이도에 따라 바꾼다.** 그러면 초급 응답에 `form` 이 없어도
파싱이 깨지지 않는다.

프롬프트에는 **그 난이도에서 요구하는 필드의 칸별 명세만** 넣는다.
초급 프롬프트에 `usage` 설명이 들어가면 모델이 `meaning` 에 섞어 쓴다.

## 6. 화면에서 어떻게 보이나

표의 열이 난이도마다 달라지면 산만하다. **`meaning` 아래에 접어서** 붙인다.

```
weigh in on   [Phrasal Verb]   의견을 내다, 개입하다
                               형태  weigh in on + 명사. on 이 반드시 붙는다
                               쓰임  공적 사안에 격식 있게 쓴다. 잡담에는 과하다
```

`form` 은 회색 작은 글씨, `usage` 는 한 단 더 들여쓰기. 없으면 줄 자체가 안 나온다.
마크다운 복사본에서는 표 아래 목록으로 붙인다(표 열을 늘리면 좁아서 깨진다).

## 7. 비용

| 난이도 | 표현 파트 출력 토큰(추정) | 분석 1회 총 LLM 호출 |
|---|---|---|
| 초급 | 현행보다 적음 | 4회 (변화 없음) |
| 중급 | 현행 + 20% | 4회 |
| 상급 | 현행 + 50% | 4회 |

호출 횟수는 늘지 않는다. 출력 토큰만 늘어난다. 회원 Gemini 무료 등급은 **요청 수**가
한도이므로 실질 영향은 작다. 로컬 모델에서는 상급 분석이 몇 초 더 걸린다.

## 8. 무엇을 재면 성공인가

구현 후 같은 지문 3개를 세 난이도로 돌려(9회 분석) 다음을 센다.

| 지표 | 기대 |
|---|---|
| `form` 필드가 채워진 비율 | 초급 0% / 중급·상급 100% |
| `usage` 필드가 채워진 비율 | 초급·중급 0% / 상급 100% |
| 세 난이도가 **같은 표현**을 고른 비율 | 30~70%. 0% 면 선정이 제멋대로, 100% 면 빈도대 구분 실패 |
| 초급 설명에 등장한 비허용 문법 용어 수 | 0 |
| 상급 결과가 중급보다 쉬운 표현을 포함 | 0건 (역전 재발 감시) |
| 항목당 평균 글자 수 | 초급 < 중급 < 상급 |

세 번째 지표가 핵심이다. **난이도가 설명만 바꾸는가, 고르는 것도 바꾸는가**를 우리가 먼저
정해야 하고, 그 결정대로 나오는지 확인해야 한다.

## 9. 결정이 필요한 것

구현 전에 정해야 한다.

1. **난이도가 선정까지 바꾸는가, 설명만 바꾸는가?**
   - (A) 설명만 — 세 난이도가 같은 표현을 고르고 설명 깊이만 다름. 비교하기 쉽고 역전 위험이 없다
   - (B) 선정도 — 2.2 의 빈도대까지 반영. 더 자연스럽지만 역전이 재발할 수 있다
   - 기획안은 **(B)** 를 전제로 썼다. (A) 로 가면 2.2 를 빼면 된다

2. **초급에 `example` 을 그대로 둘 것인가?**
   초급 학습자에게는 예문이 부담일 수 있다. 다만 작문 연습이 예문에 딸려 있어 빼면 연습도 사라진다.

3. **`form`/`usage` 를 필드로 나눌 것인가, `meaning` 안에 문장으로 둘 것인가?**
   나누면 확실히 강제되지만 화면과 마크다운을 모두 손봐야 한다.
   기획안은 나누는 쪽을 전제로 썼다.

4. **작문 연습 채점(4.4)까지 이번에 할 것인가, 분석만 먼저 할 것인가?**

## 10. 적용 순서

1. 9절 결정
2. 스키마의 `required` 를 난이도별로 바꾸는 구조 (`schema_for` 확장)
3. 표현 풀이 파트부터 적용 — 가장 자주 보는 부분이고 효과 확인이 쉽다
4. 8절 지표로 측정. **기대와 다르면 여기서 멈추고 기준을 고친다**
5. 문장 구조 파트 적용
6. 총평·작문 연습 적용
7. `documents/04-prompt-design.md` 의 난이도 절을 이 문서로 대체
