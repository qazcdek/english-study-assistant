# 08. 난이도 설계 (기획안 v2)

> 상태: **구현 완료** (표현 풀이 파트). 실측 결과는 7절.
> v1 은 Form-Meaning-Use 축으로 깊이를 갈랐으나, 더 단순하고 직접적인 축으로 다시 잡았다.

## 1. 지금 무엇이 문제인가

난이도가 실제로 바꾸는 것은 **프롬프트에 끼워 넣는 문단 하나**뿐이다.

```
초급  "문법 용어를 최소한으로 쓰고 풀어서 설명한다"
중급  "일반적인 문법 용어를 써도 좋다"
상급  "설명을 깊게 한다 — 뉘앙스 차이, 어원, 비슷한 표현과의 비교…"
```

전부 형용사와 정도부사다. "최소한으로", "깊게"가 무엇인지 모델도 모르고 우리도 모른다.
어떤 출력이 "충분히 깊은지" 판정할 기준이 없어 검증도 못 한다.

이 프로젝트에서 같은 종류의 실패를 세 번 겪었다.

| 애매한 지시 | 벌어진 일 | 해결 |
|---|---|---|
| "학습 가치가 낮은 기초 어휘는 제외" | `financial advisor` 같은 투명한 복합어만 뽑음 | 비합성성이라는 판별 기준 + 정오 예시 |
| "표현은 3~8개" | 하한만 맞추고 멈춤 | 스키마 `minItems`/`maxItems` |
| "①②③을 순서대로 쓴다" | ③을 일반론으로 때움 | 필드를 넷으로 쪼개고 `required` |

**프롬프트로 부탁하면 안 지켜지고, 스키마로 요구하면 지켜진다.** 난이도도 이 방식으로 다시 짠다.

## 2. 축을 무엇으로 잡을 것인가

**의미 칸에 무엇이 들어가는가**와 **무엇을 고르는가**, 두 가지로 가른다.

| | 초급 | 중급 | 고급 |
|---|---|---|---|
| **무엇을 고르나** | 원문의 학습 가치 있는 표현 (단일어 포함) | 초급과 같다 | **다어절 표현 중심.** 단일어는 기본 뜻과 다르게 쓰였을 때만 |
| **의미 칸** | **대역어만.** 설명 문장 없음 | 대역어 + 어떤 상황에서 쓰는지·뉘앙스 | 중급과 같다 |

초급과 중급은 **고르는 것이 같다.** 초급 학습자라고 쉬운 표현만 볼 이유가 없다 —
읽고 있는 글에 나온 이상 뜻은 알아야 한다. 다만 초급에게는 **뜻만** 알려 준다.

고급은 설명 깊이가 중급과 같고, **대상이 다르다.** 단일어는 사전을 찾으면 되지만
다어절 표현은 찾아도 안 나오거나 뜻이 갈린다. 거기가 고급 학습자가 막히는 지점이다.

### 2.1 예시

```
초급   cope with      대처하다, 감당하다
       pass muster    기준을 충족하다
       resilience     회복력

중급   cope with      대처하다, 감당하다
                      힘든 상황을 견디며 버텨낸다는 뜻. handle 보다 부담을 안고
                      감당한다는 느낌이 강하다
       resilience     회복력
                      충격을 받은 뒤 원래대로 돌아오는 힘. 경제 기사에서 시장이나
                      기업의 위기 대응력을 말할 때 자주 쓴다

고급   pass muster    기준을 충족하다
                      공적 심사를 통과한다는 뜻이라 일상 대화에는 과하다.
                      meet the standard 보다 "심사자가 있다"는 함의가 강하다
       weigh in on    의견을 내다
                      공적 사안에 격식 있게 개입할 때. 대상 앞에 on 이 반드시 붙는다
       (resilience, cope with 같은 단일어는 빠진다)
```

### 2.2 고급에서 단일어를 무조건 빼는가

아니다. **그 자리에서 사전적 기본 뜻과 다르게 쓰인 단일어는 남긴다.**

| 남긴다 | 이유 |
|---|---|
| `trumpet` | 나팔을 분다는 기본 뜻이 아니라 "떠벌리다"로 비유적으로 쓰임 |
| `yenmageddon` | 그 글에서 만들어 쓴 조어 |
| `grow`(타동사) | 자동사 "자라다"가 아니라 "자산을 늘리다" |
| `indices` | `index` 의 불규칙 복수형 |

| 뺀다 | 이유 |
|---|---|
| `resilience` `volatility` `significant` | 사전 뜻 그대로. 찾으면 나온다 |

이는 새 기준이 아니라 이미 쓰고 있는 **비합성성** 기준을 단일어에 적용한 것이다
(04-prompt-design.md 2.1.1).

## 3. 어떻게 강제할 것인가

### 3.1 의미 칸 — 필드를 나눈다 (하드 강제 가능)

`meaning` 한 칸에 "대역어 + 설명"을 섞어 두고 난이도별로 다르게 써 달라고 부탁하면
지켜지지 않는다. 구문 해설에서 이미 겪었다.

| 필드 | 초급 | 중급 | 고급 |
|---|---|---|---|
| `meaning` — 대역어 한두 개 | 필수 | 필수 | 필수 |
| **`nuance`** — 상황·뉘앙스 | **스키마에 없음** | 필수 | 필수 |

초급 스키마에서는 `nuance` 를 **속성 목록에서 아예 뺀다.** `additionalProperties: false`
이므로 모델이 그 필드를 만들어 낼 수 없다. 설명을 쓰고 싶어도 쓸 자리가 없다.

`meaning` 이라는 이름은 유지한다. 이미 저장된 분석 기록이 이 필드를 쓰고 있어,
이름을 바꾸면 옛 기록의 의미 칸이 비어 보인다.

### 3.2 고급의 "복합어만" — 스키마로는 못 한다

`pattern` 정규식으로 다어절을 강제해 보려 했으나 **두 프로바이더의 동작이 갈렸다.**

| 스키마 제약 | Gemini 3.5 Flash-Lite | llama-server (Qwen3.8-27B) |
|---|---|---|
| `maxItems` | ✓ 강제 | ✓ 강제 |
| `minItems` | ✓ 강제 | ✓ 강제 |
| `pattern` (다어절) | ✓ 강제 — `['pass muster', 'weigh in', ...]` | ✗ 생성 폭주 후 잘림, 또는 무시하고 단일어 통과 |
| `maxLength` | ✓ | ⚠ **말 도중에 싹둑 자른다** — `"대응하다, 대처하다, 감당하다, 처리"` |
| `minLength` | ✓ | ✗ 계속 쓰게 만들어 `max_tokens` 초과 |

`local` 브랜치는 llama-server 를 쓰므로 `pattern` 을 넣으면 그쪽이 깨진다.
**고급의 다어절 우선은 프롬프트 + 정오 예시로 간다.**

길이 제약도 못 쓴다. llama.cpp 의 `maxLength` 는 짧게 **쓰게** 만드는 것이 아니라
문법 단계에서 **자른다.** "대역어만 짧게"를 길이로 강제하려던 안은 폐기한다.

### 3.3 개수 하한은 글 길이에서 계산한다

하한을 난이도에 고정해 두면, 짧은 글에서 모델이 그 숫자를 채우려고 규칙을 어긴다.
상급 하한이 7이던 때 `a blend of` 를 `blend` 로 쪼갠 것이 그 예다.
고급은 다어절만 고르므로 이 문제가 더 심해진다 — 짧은 대화문에는 다어절이 3개도 없다.

**상한만 난이도를 따르고, 하한은 글 길이에서 구한다.**

```python
CHARS_PER_EXPRESSION = 200

def min_expressions(text_length, max_items):
    wanted = max(1, text_length // CHARS_PER_EXPRESSION)
    return max(1, min(wanted, max_items - 1))
```

```python
MAX_MIN_EXPRESSIONS = 3   # 하한이 아무리 올라가도 여기서 멈춘다
```

| 글자 수 | 하한 |
|---|---|
| ~399 | 1 |
| 400~599 | 2 |
| 600 이상 | 3 |

**하한에 상한(3)을 둔 이유**는 고급이다. 고급은 다어절만 고르는데 긴 글이라고 하한이
계속 올라가면, 다어절이 모자란 순간 모델이 단일어를 끌어온다.

**하한은 "적어도 이만큼은"이지 "이만큼을 채워라"가 아니다.**

### 3.4 너무 짧은 입력은 아예 받지 않는다

20자 이하는 프론트에서 막는다. 한두 낱말로는 문맥이 없어 번역·구조·총평이 모두 공허해지고,
그 한 번에도 LLM 호출 네 번이 들어간다.

버튼을 비활성화하지 않고 **누르면 안내가 뜨게** 했다. 막아 두기만 하면 왜 안 되는지 알 수 없다.
잠깐 떴다 사라지는 알림(`Toast`)을 쓰고, 글자수 표시에도 `12 / 800자 — 20자 이상` 으로 덧붙인다.

### 3.5 코드 가드는 두지 않는다

"고급에서 단일어를 코드로 걸러내자"는 안이 있었으나 **쓰지 않는다.**
`yenmageddon`, `trumpet`(비유), `grow`(타동사) 처럼 남겨야 할 단일어를
낱말 수로는 구분할 수 없다. 규칙으로 확실히 판별되는 것만 코드로 잡는다는
`refine.py` 의 원칙에 어긋난다.

## 4. 파트별 적용 범위

이번 단계는 **표현 풀이만** 바꾼다. 가장 자주 보는 부분이고 효과 확인이 쉽다.

| 파트 | 이번에 | 이유 |
|---|---|---|
| 표현 풀이 | **바꾼다** | 난이도 차이가 가장 크게 드러나는 곳 |
| 문장 구조 | 그대로 | 이미 네 필드로 나뉘어 있다. 난이도 연동은 측정 후 판단 |
| 총평 | 그대로 | |
| 작문 연습 | 그대로 | |

## 5. 화면과 마크다운

표에 열을 늘리면 좁아서 깨진다. `meaning` 아래 줄에 붙인다.

```
cope with   [연어]   대처하다, 감당하다
                     힘든 상황을 견디며 버텨낸다는 뜻. handle 보다 부담을 안고
                     감당한다는 느낌이 강하다        ← nuance, 회색 작은 글씨
```

초급에서는 둘째 줄이 아예 없다. 마크다운 복사본도 같은 방식으로 붙인다.

## 6. 비용

LLM **호출 횟수는 변하지 않는다**(분석 1회 = 4회). 출력 토큰만 바뀐다.

| 난이도 | 표현 파트 출력 |
|---|---|
| 초급 | 현행보다 **줄어든다** (설명 문장이 사라짐) |
| 중급 | 현행과 비슷 |
| 고급 | 현행과 비슷 |

Gemini 무료 등급은 요청 수가 한도이므로 실질 영향은 없다.

## 7. 실측 결과

금융 칼럼 398자를 세 난이도로 돌렸다 (Gemini 3.5 Flash-Lite).

| 지표 | 기대 | 실제 |
|---|---|---|
| `nuance` 채워진 비율 | 초급 0% / 중급·고급 100% | 0% / 100% / 100% ✓ |
| 초급 `meaning` 에 종결어미 문장 | 0% | 0% ✓ |
| 초급 `meaning` 평균 길이 | 20자 이하 | 약 11자 ✓ |
| 고급에 남은 단일어가 비합성적인가 | 전부 | `yenmageddon`(조어), `indices`(불규칙 복수) ✓ |
| 초급이 고른 표현이 중급에 포함되는가 | 대부분 | 3개 전부 포함 ✓ |
| 고급 표현 중 다어절 비율 | 70% 이상 | **60%** (5개 중 3개) |

```
초급   grow wealth      자산을 늘리다, 부를 증식하다
       yenmageddon      엔화 급락 및 시장 혼란 사태
       panic selling    공황 매도
       (설명 줄 없음)

고급   a blend of       조합, 융합
                        ↳ 단순한 물리적 혼합보다는 화학적 융합의 뉘앙스가 강하다
       grow wealth      자산을 늘리다, 부를 증식하다
                        ↳ 일반적으로 grow 는 자동사로 쓰이지만 목적어를 취하는 타동사로…
       indices          지수들
                        ↳ index 의 불규칙 복수형이다. 격식 있는 금융 리포트에서 주로 쓴다
```

**다어절 비율만 기준에 못 미쳤다.** 다만 남은 단일어가 `yenmageddon` 과 `indices` 로
정확히 의도한 예외다. 지표를 "다어절 비율"이 아니라 **"남은 단일어가 전부 비합성적인가"**
로 바꾸는 것이 옳다. 비율로 재면 `indices` 를 잘못 뽑은 것처럼 보인다.

### 남은 관찰

초급이 3개, 중급·고급이 5개를 뽑았다. 고르는 기준은 같지만 상한이 다르고(초급 5, 나머지 8)
하한이 낮아 모델 재량이 넓다. 초급 학습자에게 8개는 부담이므로 지금은 그대로 둔다.

## 8. 결정된 것

1. **고급에서 다어절이 부족한 글** → 하한을 글 길이에서 계산하고 **상한을 3으로** 둔다.
2. **초급의 `example`** → **남긴다.** 작문 연습이 예문에 딸려 있어 빼면 연습도 사라진다.
   설명 문장만 없애고 예문은 세 난이도 모두 그대로다.

## 9. 적용 순서

1. `PartSpec.schema_for(level)` 을 확장해 **속성 목록과 `required` 를 난이도별로** 바꾼다
2. `Expression` 에 `nuance` 추가 (기본값 `""`, 옛 기록 호환)
3. 표현 풀이 프롬프트를 난이도별로 조립 — 초급 프롬프트에는 `nuance` 설명을 넣지 않는다
4. 화면·마크다운에 둘째 줄 추가
5. 7절 지표로 측정. **기대와 다르면 여기서 멈추고 기준을 고친다**
6. 04-prompt-design.md 의 난이도 절을 이 문서로 대체
