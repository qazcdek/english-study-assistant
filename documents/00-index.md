# 00. 문서 지도

> **층** 메타 · **상태** 유효 · **강제** `./dev.sh docs` · `backend/tests/test_docs_graph.py`
> **읽어야 할 때** 어떤 문서를 봐야 할지 모를 때. 새 문서를 만들 때
> **위** [CLAUDE.md](../CLAUDE.md) · **아래** 이 문서가 모든 문서를 가리킨다

**색인은 여기 하나뿐이다.** README 나 다른 문서에 목록을 복사하지 않는다 — 둘이 되면 갈라진다.

이 문서는 **어디에 무엇이 있는지**를 든다. **왜 이렇게 설계했는지**는
[11 문서 아키텍처](11-docs-architecture.md), **무엇을 지켜야 하는지**는 [CLAUDE.md](../CLAUDE.md).

```
CLAUDE.md                 메타 규약. 세션마다 자동으로 읽힌다
└── 00-index.md           이 문서. 모든 문서로 가는 유일한 입구
    ├── 메타   11          문서 체계 자신에 관한 것
    ├── 제품   01
    ├── 설계   02 03 04 06
    ├── 규약   09 10
    ├── 운영   07
    ├── 기록   05 08
    └── 진행   plan/ROADMAP · plan/ISSUES · plan/DONE
```

## 1. 층이 뜻하는 것

| 층 | 무엇인가 | 어긋나면 |
|---|---|---|
| **메타** | 문서 체계 자신에 관한 것 (이 문서와 [11](11-docs-architecture.md)) | 문서가 쌓이기만 하고 안 읽힌다 |
| **제품** | 무엇을 왜 만드는가 | 기능이 목적에서 멀어진다 |
| **설계** | 어떻게 만들었는가 | 코드를 읽어야만 알 수 있게 된다 |
| **규약** | **반드시 지켜야 하는 것.** 대개 테스트나 린트가 강제한다 | 테스트가 깨지거나, 같은 실수가 반복된다 |
| **운영** | 띄우고 유지하는 법 | 배포가 막힌다 |
| **기록** | 그때의 측정·판단. **고치지 않는다** | 왜 그렇게 정했는지 사라진다 |
| **진행** | 지금 무엇을 하고 있는가 | 할 일을 놓친다 |

**상태**는 셋뿐이다.

- **유효** — 지금 코드가 이대로다. 코드를 바꾸면 이 문서도 바꾼다.
- **기록** — 그때의 측정이거나 판단이다. **다시 재거나 다시 정하기 전까지 손대지 않는다.**
- **대체됨** — 다른 문서로 넘어갔다. 머리말에 넘어간 곳을 적는다.

ROADMAP 과 ISSUES 는 같은 방식으로 적는다 — 체크박스 + 태그 + 한 줄 요약.
둘 다 끝나도 줄을 지우지 않고 `[x]` 로 체크만 하고, 세부는 DONE 으로 옮긴다.
그래서 **상태는 그 체크박스 하나뿐이고 세부는 DONE 한 군데에만 있다.**

#### T 와 H 를 가르는 기준

- **T (task)** — **의도한 것.** 만들기로 계획한 일. 마일스톤에 묶인다. `M2-T3`
- **H (hotfix)** — **의도치 않은 것.** 만드는 과정에서 드러난, 이미 있는 동작의 결함.
  마일스톤에 묶이지 않고 전역 연번. `H-012`

"아직 안 만든 기능"은 H 가 아니라 T 다. 판단이 애매하면 **지금 동작이 잘못됐나**를 묻는다.

## 3. 파일명과 절 번호를 바꾸지 않는다

코드 주석이 경로와 절 번호로 문서를 가리킨다. 옮기거나 번호를 다시 매기면 전부 썩는다.

```
app/config.py            09-mode-matrix.md 3.1
app/schemas.py           09-mode-matrix.md 3.1
app/routers/analyze.py   09-mode-matrix.md 3.1, 3.3
app/services/records.py  04-prompt-design.md 7절
app/prompts/analysis.py  05-benchmark.md
app/prompts/practice.py  06-practice.md
app/providers/llama_server.py  05-benchmark.md
app/auth/google.py       07-web-deployment.md
tests/modes.py           09-mode-matrix.md 3.4, 6.1
tests/test_mode_matrix.py  09-mode-matrix.md 2·3절
```

**번호는 뜻이 아니라 주소다.** 층이 바뀌어도 번호는 그대로 두고, 새 문서는 `10-`, `11-` 로 이어 붙인다.

## 4. 새 문서를 만들 때

1. 층을 정한다 (위 표). 층이 안 정해지면 **새 문서가 필요한 게 아니다** — 기존 문서의 절로 들어간다.
2. 다음 번호를 붙인다.
3. **표준 머리말**을 단다 (아래 4.1). `위` 가 없으면 고아가 된다.
4. 이 문서의 목록에 한 줄 추가한다.
5. `./dev.sh docs` 로 확인한다 (끊긴 링크 · 머리말 · 색인 · 태그 정합성).

### 4.1 표준 머리말

모든 문서는 제목 바로 아래에 이 블록을 둔다. **형식이 같아야 훑을 수 있다.**

```markdown
# 10. 제목

> **층** 설계 · **상태** 유효 · **강제** `tests/test_xxx.py`   ← 강제는 있을 때만
> **읽어야 할 때** 어떤 작업을 시작할 때 이 문서를 펴야 하는가
> **위** [문서 지도](00-index.md) · **함께** [02](02-architecture.md) · [03](03-api-spec.md)
```

- **위** 는 되돌아 나가는 길이다. 모든 문서가 가져야 **고아와 막다른 문서가 안 생긴다.**
- **읽어야 할 때** 는 색인이 아니라 **문서 자신이** 들고 있어야 한다.
  색인을 안 보고 문서에 바로 들어오는 경우가 더 많다.
- **강제** 는 그 문서를 지키게 하는 테스트다. 있으면 그 문서는 설명이 아니라 명세다.
