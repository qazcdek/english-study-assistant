# 06. 작문 연습 기능

> **층** 설계 · **상태** 유효
> **읽어야 할 때** 작문 연습 기능을 건드릴 때
> **위** [문서 지도](00-index.md) · **함께** [제품 기획서](01-product-spec.md) · [프롬프트 설계](04-prompt-design.md) · [API 명세](03-api-spec.md)

표현 풀이 표의 예문을 가리고, 한국어 뜻만 보고 영어 문장을 직접 써 본 뒤
LLM이 채점하는 기능. 표의 각 행에서 바로 시작한다.

## 1. 교육학적 근거

세 가지가 맞물린다.

| 근거 | 설계에 반영된 것 |
|---|---|
| **Pushed output (Swain)** | 읽고 이해하는 것은 의미 처리만으로 되지만, 직접 쓰려면 문법을 강제로 인코딩해야 한다. 총평의 "수용 vs 표현" 구분(04-prompt-design.md 2.5)을 실제 활동으로 옮긴 것이다 |
| **인출 연습(retrieval practice)** | 답을 가리고 떠올리게 하는 것이 다시 읽기보다 낫다 → 예문을 **기본값으로 가린다** |
| **Noticing the gap (Schmidt/Swain)** | 학습이 일어나는 지점은 자기 문장과 모범 답안을 비교하는 순간이다 → 모범 답안은 **시도 이후에만** 보이고, 나란히 놓는 데 그치지 않고 차이를 짚어 준다 |

### 1.1 설계에서 피해야 할 세 가지

1. **모범 답안과 다르다고 틀린 것이 아니다.**
   같은 한국어를 영어로 옮기는 방법은 여럿이다. LLM 채점의 가장 큰 오판 지점이라
   프롬프트 맨 앞에 못박았다.
2. **피드백은 선별적이어야 한다.**
   그냥 첨삭시키면 관사·전치사·구두점까지 지적해 학습자가 압도된다.
   Lyster & Ranta 의 교정 피드백 연구상 **목표 표현에 집중한 메타언어적 설명**이
   단순 재진술(recast)보다 흡수율이 높다. 부차적 지적은 **최대 2개**로 제한한다
   (프롬프트로 지시하고, 서비스 코드에서 한 번 더 자른다).
3. **잘한 점을 먼저 인정한다.**
   정의적 여과(affective filter) 문제이기도 하고, 무엇을 유지해야 할지 알려 주는 정보이기도 하다.
   "다시" 판정이어도 `good_point` 는 반드시 채운다.

### 1.2 알려진 한계

한국어 제시문에서 출발하는 방식은 **직역체를 유도할 위험**이 있다.
성인 학습자에게 목표 표현을 반드시 쓰게 만드는 제약으로는 효율적이라 채택했고,
대신 `other_notes` 에서 직역체를 우선 지적하도록 프롬프트에 넣었다.

## 2. UI

작문 연습은 **그 표현 하나에 대한 퀴즈**이므로, 표 안에서 모든 컬럼을 합친 한 행으로 펼친다
(`<td colSpan>`). 의미 칸 안에 끼워 넣으면 폭이 좁아 읽기 불편하다.

```
┌ 표현 풀이 ───────────────────────── ☑ 예문 가리고 직접 써보기 ┐
│ 표현          유형          의미 및 설명           예문       │
│ ─────────────────────────────────────────────────────────── │
│ ★ weigh in on [Phrasal Verb] 의견을 내다…    [✏ 직접 써보기] │
│ ┌─────────────────── 전체 폭 한 행 ──────────────────────┐   │
│ │ [작문 연습] weigh in on 을(를) 써서…            닫기   │   │
│ │ │ CEO가 그 논쟁에 대해 의견을 내기로 결정했다.          │   │
│ │ ┌──────────────────────────────────┐ [채점하기] ⌘↵    │   │
│ │ │ 영어로 써 보세요                  │                  │   │
│ │ └──────────────────────────────────┘                  │   │
│ └────────────────────────────────────────────────────────┘   │
│ ★ pass muster  [관용구]      기준을 충족하다… [✏ 직접 써보기] │
└──────────────────────────────────────────────────────────────┘
```

채점 후 같은 자리에서. **내 문장과 모범 답안을 나란히** 둔다 — 넓은 폭을 살려
1.1 의 noticing the gap 이 한눈에 일어나게 하기 위해서다.

```
│ △ 통함   목표 표현 사용함                        [다시 써보기] │
│ 내 문장                          모범 답안                    │
│ The experts are weighing in      Experts are weighing in on   │
│ about the new policy.            the new policy.              │
│ ───────────────────────────────────────────────────────────── │
│ 잘한 점    진행 시제를 써서 진행 중인 의견 개입을 표현했다      │
│ 목표 표현  weigh in 은 'on' 과 함께 쓰는 것이 관용적이며…      │
│ 고쳐 쓰면  The experts are weighing in on the new policy.      │
│ 그 밖에    (최대 2개)                                          │
```

### 2.1 세부 규칙

- **예문 가리기 토글**은 표 상단 오른쪽. 기본값은 **가림**이다. 끄면 예문이 그대로 보이고
  연습 버튼이 사라진다 — 그냥 읽고 싶을 때를 위한 것이다.
- **예문 컬럼 폭은 모드에 따라 다르다.** 가릴 때는 버튼만 들어가므로 유형 칸과 같은
  `14%`(측정값 117px, 버튼 90px)이고, 예문을 보일 때만 `22%`로 넓힌다.
  남는 폭은 의미 및 설명 칸이 가져간다(318px → 386px).
- 한 번에 한 행만 열린다. 다른 행을 열면 이전 것은 닫힌다.
- 열린 행과 연습 행은 같은 배경색으로 묶어 한 덩어리로 보이게 한다.
- 예문이 없는 행(`example` 을 생략한 경우)은 연습할 수 없고 `—` 로 표시한다.

## 3. 데이터 흐름

한국어 제시문은 **표현 풀이 파트에서 예문과 함께 생성**한다(`example_ko`).
연습 시작 시점에 번역을 따로 호출하면 학습자가 쓰기 시작하기 전에 한 번 더 기다려야 하기 때문이다.

```
분석 (POST /api/analyze/stream)
  └ expressions 파트가 example 과 example_ko 를 함께 생성
        │
        ▼  학습자가 [✏ 직접 써보기] 를 누르고 영작
채점 (POST /api/practice)
  expression / meaning / prompt_ko / model_answer / learner_answer / level
  + type / source_text   ← 채점에는 안 쓰인다. 나의 표현에 올릴 때 쓴다
        ▼
  verdict · uses_target · good_point · target_note · corrected · other_notes
        │
        ├─ practices      에 기록으로 남는다
        └─ vocabulary     에 이 표현이 자동으로 올라간다 (한 트랜잭션)
```

**기록과 등록은 같은 트랜잭션에서 한다.** 나의 표현이 연습 기록으로 가는 유일한
입구이므로, 기록만 남고 등록이 빠지면 **아무 화면에도 안 나타나는 유령 데이터**가 된다.
채점과 등록을 두 번 호출하게 하면 뒤쪽이 실패하는 순간 그 일이 벌어지고,
사용자 눈에 안 보이므로 아무도 고치지 않는다. 같은 종류의 버그를 이미 겪었다 —
예문이 비면 체크박스까지 사라져 입구가 통째로 없어졌다(H-019).
`→ backend/app/services/vocabulary.py`

**제외하면 그 표현의 연습 기록도 사라진다.** 되돌릴 수 없으므로 화면이 먼저 묻는다.
API 는 묻지 않는다.

### 3.1 들어가는 자리가 둘이다

```
표현 풀이의 행에서          방금 분석한 표현을 바로 써 본다
나의 표현 목록에서          담아 둔 표현을 다시 써 본다 (복습)
```

**둘이 같은 `PracticeBox` 를 쓴다.** 비슷한 것을 하나 더 만들면 한쪽만 고쳐져 갈라지고,
학습자는 같은 기능이 자리에 따라 다르게 동작하는 것을 본다. 목록 쪽은 담아 둔 항목을
분석 결과의 표현과 같은 모양으로 바꿔서 넘긴다 (`asExpression`).

난이도는 **지금 화면에 선택된 값**을 쓴다. 담아 둘 때의 난이도를 따라가지 않는다 —
복습하는 지금의 수준으로 채점받는 것이 맞다.

### 3.2 쓴 기록을 되돌려 볼 때

```
나의 기록 보기      ▾   어떤 제시문으로 써봤나
  제시문
  내가 쓴 답안 보기  ▾   내 문장 + 일시 (yyyy-mm-dd hh:mm:ss)
    자세히 보기      ▾   모범 답안 + 그때 AI 가 매긴 평가
```

**세 겹이고, 각 겹이 다른 정보를 더한다.** 한 겹이라도 합치면 훑을 수가 없다 —
처음에 판정·내 문장·모범 답안을 한 줄에 다 깔아 봤는데, 같은 한국어 제시문이 시도마다
반복되면서 **정작 다른 부분인 내 문장이 묻혔다.**

**기록은 제시문으로 묶는다.** 같은 표현을 여러 번 써보면 답안이 한 제시문 아래로 모여야
"몇 번째 시도에서 달라졌나" 가 보인다. 제시문이 여럿일 수 있다 — 같은 표현이 다른 글에서
또 나오면 예문이 갱신되고, 옛 기록은 그때 받은 제시문을 그대로 들고 있다.

일시는 **연월일 시분초**다. 날짜만으로는 같은 날 여러 번 쓴 것이 구별되지 않는다.

**판정은 접힌 줄에 두지 않는다.** 답안을 훑을 때 보고 싶은 것은 "내가 뭐라고 썼나" 이고,
잘했는지는 그다음 질문이다. 판정도 AI 가 매긴 것이므로 평가와 같은 자리에 둔다.

펼친 버튼은 모두 **`접기`** 가 된다. 세 겹이 같은 모양이어야 어디를 누르면 뭐가 열리는지
한 번만 익힌다.

평가를 그리는 부분은 채점 직후와 나중에 되돌려 볼 때가 **한 컴포넌트**다
(`PracticeFeedback`). 베껴 쓰면 한쪽만 고쳐져 갈라지고, 그때 "전에 본 평가와 다르다" 는
의심이 생기면 **기록 자체를 못 믿게 된다.**

접힌 채로는 **예문을 보여주지 않는다.** 답을 먼저 보면 복습이 성립하지 않는다 —
표현 풀이에서 예문을 가리는 것과 같은 이유다 (2절).

`example` 은 "확신할 때만" 넣게 되어 있어 생략될 수 있고, 그때는 `example_ko` 도 함께 생략된다.

## 4. 판정 기준

| verdict | 뜻 |
|---|---|
| `정확함` | 목표 표현을 바르게 썼고, 문법적으로 맞으며 원어민이 쓸 법하다 |
| `통함` | 뜻은 전달되지만 어색하거나, 목표 표현의 용법이 살짝 어긋난다 |
| `다시` | 목표 표현을 쓰지 않았거나 틀리게 썼다. 또는 뜻이 제시문과 달라졌다 |

`uses_target` 은 판정과 별개로 표시한다. 이 연습의 목적이 목표 표현을 직접 써 보는 것이기 때문이다.
활용형이 달라도(sums up / summed up) 같은 표현이면 사용한 것으로 본다.

## 5. 실측

Qwen3.8-27B, 채점 1회당 **5~7초**.

레이아웃은 Chrome(puppeteer-core)으로 실제 렌더링해 확인했다 —
연습 행의 `colSpan` 이 헤더 칸 수와 일치하고, 셀·박스 폭이 표 전체 폭과 같다.

| 입력 | 결과 |
|---|---|
| 모범 답안과 어휘·구조가 모두 다른 올바른 문장<br>`The firm loudly trumpeted its latest product as a breakthrough.` | **정확함**, 고칠 것 없음 — 1.1-1 의 오판이 일어나지 않았다 |
| 목표 표현을 안 쓴 문장 (`advertised` 로 대체) | **다시**, `uses_target: false`. 왜 trumpet 이 더 적합한지 뉘앙스로 설명 |
| 용법이 틀린 문장 (`trumpeted about`) | **통함**. "trumpet 은 타동사이므로 목적어를 바로 받거나 trumpet something as something 구조를 써야 한다" — 규칙을 설명하고 최소 수정 |
| 직역체 + 수동태 오용 | **다시**. 학습자 어휘를 살린 최소 수정, 부차적 지적 1개 |

분석에서 나온 `example_ko` 를 그대로 제시문으로 넘겨 채점까지 이어지는 것도 확인했다.

## 6. 남은 것

- **틀린 표현만 모아 다시 푸는 화면이 없다.** 기록은 쌓이고 `verdict` 로 거를 수도 있는데
  (`GET /api/practice/history?verdict=다시`) 그걸 쓰는 화면이 아직 없다 (M2-T3).
- 같은 표현을 여러 번 연습하면 기록이 그대로 쌓인다. 몇 번째 시도에서 맞았는지는
  나의 표현에서 펼쳐 봐야 안다. 추이를 요약해 보여주지 않는다.
- 모델이 문법 용어를 헐겁게 쓰는 문제는 여기서도 나타난다
  ("타동사 구동사(phraseological verb)"). 04-prompt-design.md 8절과 같은 한계다.
